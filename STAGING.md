# Staging и управление ветками

## Основные ветки

### `main` — Production
- Стабильная версия сайта
- Текущие маршруты остаются неизменными:
  - `/` — главная страница
  - `/portfolio/` — портфолио
  - `/blog/` — блог
  - `/about/` — о проекте
- Все изменения в `main` должны быть протестированы
- Деплой происходит автоматически из этой ветки

### `staging` — Новая структура
- Экспериментальная ветка для новой архитектуры контента
- Включает:
  - Новую папку `content/` с подразделами (web, ai, infrastructure, culture, method, studio)
  - Страницу `/studio/` — студийная экосистема
  - Коллекцию `articles` в Content Collections
  - Новую схему метаданных для статей (Zod-схема)
  - Черновики контента в `content/ai/`

## Workflow

1. **Все изменения структуры, таксономии, новых коллекций и экспериментальных страниц** → `staging`
2. **Визуальная проверка** сборки и функциональности в `staging`
3. **Merge в `main`** только после подтверждения, что:
   - Сборка проходит без ошибок
   - Существующие маршруты не сломаны
   - Новая функциональность работает корректно
   - SEO-оптимизация сохранена

## Что находится в staging

- `content/` — новая структура папок для контента
- `content/ai/itwo-20251028-studio-ekosistema.md` — черновик статьи
- `src/content.config.ts` — добавлена коллекция `articles`
- `src/pages/studio.astro` — новая страница (не в навигации)

## Важно

- Существующая структура `src/content/blog/` продолжает работать
- Страницы `/about/` и `/portfolio/` не затронуты
- Навигация сайта не изменена
- Новая структура — это дополнение, а не замена

## Проверка перед merge

```bash
# В ветке staging
npm run build
# Убедиться, что сборка успешна

# Проверить локально
npm run preview
# Протестировать все маршруты

# После успешной проверки
git checkout main
git merge staging
git push origin main
```
